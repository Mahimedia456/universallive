# UniversalLive Phases 24-26

## Phase 24 - Mobile auth/session contract
- Supabase Auth remains identity provider.
- Mobile obtains an access token using the publishable key.
- NestJS accepts only Bearer access tokens and resolves `/auth/me`.
- Session persistence contract added; platform implementation comes from Android secure storage/network layer.

## Phase 25 - Cloud destinations/settings/scenes
New API routes:
- `GET/POST/DELETE /api/v1/destinations`
- `GET/PUT /api/v1/settings`
- `GET/POST/DELETE /api/v1/scenes`
Run `backend/supabase/migrations/0002_cloud_sync.sql` after migration 0001.
Stream keys are not stored in plaintext by these endpoints; `secret_ref` is intended to point at a secure secret/vault record in the next security phase.

## Phase 26 - Stream session sync contract
The mobile cloud API contract covers start/status/metrics/stop/active/history orchestration. Native streaming remains direct RTMP/RTMPS from the device; backend is the control plane.

## Clean project rule
No SizeME modules such as measurements, scans, recommendations, or size-charts are included in UniversalLive.
